# MetroLink

## Problem Statement
Campus donation drives collect clothes and books from students but lack a system to log what was collected and where it was distributed. 

## Project Objective
Build a Spring Boot backend that records donated items per drive and tracks their distribution to recipient organizations.

## Features
- Create and manage Donation Drives (start and end dates).
- Log donated items with category, condition, and donor name.
- Record distribution of items to a recipient organization.
- View total items collected, distributed, and undistributed per drive.
- List undistributed items remaining in stock.
- Basic search and filter by date and category.
- Dashboard with total counts.

## Technology Stack
- Java 21
- Spring Boot (Spring Web, Spring Data JPA, Spring Validation)
- MySQL
- Maven
- Lombok
- Springdoc OpenAPI (Swagger)

## Architecture
This project follows a clean layered architecture:
- `Controller Layer`: Exposes REST endpoints.
- `Service Layer`: Contains all business logic and validations.
- `Repository Layer`: Handles database interactions using Spring Data JPA.
- `Entity Layer`: Maps Java classes to Database tables.
- `DTO Layer`: Isolates incoming and outgoing data structures.

## Entity Relationships
- `Drive` (1) ------ (*) `DonatedItem`
- `Donor` (1) ------ (*) `DonatedItem`
- `Recipient` (1) ------ (*) `DonatedItem`

## Business Rules
- **Distribution only after collection**: An item can be distributed only if its status is `COLLECTED`.
- **Item distributed only once**: If an item's status is `DISTRIBUTED`, it cannot be distributed again.
- **Condition constraints**: Items must be categorized as `NEW`, `GOOD`, or `WORN`.
- **Category constraints**: Items must be either `CLOTHES` or `BOOKS`.
- **Date validation**: A drive's start date must not be after its end date.
- **Reference validation**: Items must reference valid Drive, Donor, and Recipient IDs.

## Database Setup
1. Install MySQL.
2. Create a database: `CREATE DATABASE donatehub;`
3. The schema will be automatically generated by Hibernate (`ddl-auto=update`).
4. Update `application.properties` with your database username and password using environment variables `DB_USERNAME` and `DB_PASSWORD`, or replace them directly.

## How to Run Backend
1. Clone the repository.
2. Navigate to the project root directory.
3. Run `mvn clean install` to build the project.
4. Run `mvn spring-boot:run` to start the application.
5. The application will be running on `http://localhost:8080`.

## Swagger Instructions
Once the application is running, access the Swagger UI to view and test all endpoints:
`http://localhost:8080/swagger-ui.html`

## Postman Testing Instructions
Import the endpoints into Postman and test them. Ensure to pass valid JSON payloads for POST and PUT requests. All API endpoints follow standard REST conventions.

## API Endpoint List
### Drive
- `POST /api/drives`
- `GET /api/drives`
- `GET /api/drives/{id}`
- `PUT /api/drives/{id}`
- `DELETE /api/drives/{id}`
- `GET /api/drives/{driveId}/summary`

### Donor
- `POST /api/donors`
- `GET /api/donors`
- `GET /api/donors/{id}`
- `PUT /api/donors/{id}`
- `DELETE /api/donors/{id}`

### Recipient
- `POST /api/recipients`
- `GET /api/recipients`
- `GET /api/recipients/{id}`
- `PUT /api/recipients/{id}`
- `DELETE /api/recipients/{id}`

### Donated Item
- `POST /api/items` (Log Item)
- `GET /api/items` (Supports query params `?category=BOOKS` or `?date=2026-09-05`)
- `GET /api/items/{id}`
- `PUT /api/items/{id}`
- `DELETE /api/items/{id}`
- `POST /api/items/{itemId}/distribute` (Distribute Item)
- `GET /api/items/undistributed`

### Dashboard
- `GET /api/dashboard`
